# Feature Specification: 密码重置与邮箱验证

**Feature Branch**: `006-password-reset-email-verification`  
**Created**: 2025-11-01  
**Status**: Draft  
**Input**: User description: "忘记密码、邮箱验证"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 忘记密码重置流程 (Priority: P1)

用户忘记了登录密码，需要通过邮箱验证重置密码以重新获得账户访问权限。

**Why this priority**: 密码重置是账户恢复的核心功能，直接影响用户能否访问系统。没有此功能，忘记密码的用户将永久失去账户访问权限。

**Independent Test**: 用户可以通过"忘记密码"链接完成整个重置流程并成功登录，无需依赖其他功能。

**Acceptance Scenarios**:

1. **Given** 用户在登录页面，**When** 点击"忘记密码"链接，**Then** 显示密码重置请求页面
2. **Given** 用户在密码重置请求页面，**When** 输入注册邮箱并提交，**Then** 系统发送包含重置链接的邮件到该邮箱
3. **Given** 用户收到重置邮件，**When** 点击邮件中的重置链接，**Then** 打开密码重置表单页面
4. **Given** 用户在密码重置表单页面，**When** 输入新密码并确认提交，**Then** 密码更新成功，显示成功消息并引导用户登录
5. **Given** 用户密码已重置，**When** 使用新密码登录，**Then** 成功登录系统
6. **Given** 用户请求了密码重置但未完成，**When** 重置链接过期后尝试使用，**Then** 显示链接已失效提示

---

### User Story 2 - 注册时邮箱验证 (Priority: P2)

新用户注册账户后，需要验证邮箱地址以确保邮箱有效性和账户安全性。

**Why this priority**: 邮箱验证可以防止恶意注册、确保密码重置功能可用，但不是立即阻止用户使用系统的硬性要求。

**Independent Test**: 用户注册后收到验证邮件，点击验证链接完成验证，账户状态更新为已验证。

**Acceptance Scenarios**:

1. **Given** 用户完成注册表单提交，**When** 注册成功，**Then** 系统自动发送验证邮件到注册邮箱
2. **Given** 用户收到验证邮件，**When** 点击邮件中的验证链接，**Then** 邮箱验证成功，显示成功页面
3. **Given** 用户邮箱已验证，**When** 查看账户信息，**Then** 显示"邮箱已验证"状态
4. **Given** 用户邮箱未验证，**When** 登录系统，**Then** 显示邮箱验证提醒横幅（不阻止登录）
5. **Given** 验证链接已过期，**When** 用户点击过期链接，**Then** 显示链接失效提示并提供重新发送选项

---

### User Story 3 - 重新发送验证邮件 (Priority: P3)

用户未收到验证邮件或验证链接已过期，需要请求重新发送验证邮件。

**Why this priority**: 这是邮箱验证功能的补充，处理邮件未送达或过期的情况，优先级相对较低。

**Independent Test**: 用户在账户设置或验证提醒中点击"重新发送验证邮件"，收到新的验证邮件并成功验证。

**Acceptance Scenarios**:

1. **Given** 用户邮箱未验证，**When** 点击"重新发送验证邮件"按钮，**Then** 系统发送新的验证邮件
2. **Given** 用户短时间内多次请求发送，**When** 请求频率超过限制，**Then** 显示冷却时间提示（防止滥用）
3. **Given** 用户收到新的验证邮件，**When** 点击新链接，**Then** 验证成功（旧链接自动失效）

---

### User Story 4 - 更改邮箱地址 (Priority: P4)

已登录用户需要更改账户绑定的邮箱地址。

**Why this priority**: 这是账户管理的增强功能，但不是密码重置和邮箱验证的核心需求。

**Independent Test**: 用户在账户设置中输入新邮箱，通过验证后成功更改邮箱。

**Acceptance Scenarios**:

1. **Given** 用户在账户设置页面，**When** 输入新邮箱地址并提交，**Then** 系统发送验证邮件到新邮箱
2. **Given** 用户收到新邮箱验证邮件，**When** 点击验证链接，**Then** 新邮箱验证成功，账户邮箱更新
3. **Given** 用户正在更改邮箱，**When** 在新邮箱验证前，**Then** 旧邮箱仍然有效
4. **Given** 用户更改邮箱后，**When** 新邮箱验证成功，**Then** 系统发送通知邮件到旧邮箱（安全通知）

---

### Edge Cases

- 用户输入不存在的邮箱地址请求密码重置时如何处理？（不应泄露邮箱是否存在）
- 用户同时有多个未过期的密码重置链接时如何处理？
- 邮件发送失败（SMTP错误、邮箱不存在、被拒收）时如何处理？
- 用户在密码重置过程中已经通过其他方式成功登录，重置链接是否仍然有效？
- 恶意用户频繁请求发送验证邮件或重置邮件，如何防止滥用？
- 用户使用过期的验证链接或重置链接时的友好提示和补救措施
- 用户更改邮箱但新邮箱已被其他账户使用时如何处理？

## Requirements *(mandatory)*

### Functional Requirements

#### 密码重置功能

- **FR-001**: 系统必须在登录页面提供"忘记密码"链接入口
- **FR-002**: 系统必须提供密码重置请求页面，用户输入注册邮箱后提交请求
- **FR-003**: 系统必须生成带有唯一令牌的密码重置链接，令牌有效期为24小时
- **FR-004**: 系统必须通过邮件将密码重置链接发送到用户注册邮箱
- **FR-005**: 密码重置邮件必须包含：重置链接、有效期说明、安全提示（如果非本人操作请忽略）
- **FR-006**: 系统必须验证重置令牌的有效性（未过期、未使用、匹配用户）
- **FR-007**: 系统必须提供密码重置表单页面，要求用户输入新密码（两次确认）
- **FR-008**: 新密码必须满足密码强度要求（至少8个字符，包含字母和数字）
- **FR-009**: 密码重置成功后，令牌必须立即失效，无法再次使用
- **FR-010**: 密码重置成功后，系统必须发送确认邮件到用户邮箱
- **FR-011**: 系统必须对密码重置请求进行频率限制（同一邮箱5分钟内最多请求3次）
- **FR-012**: 为防止邮箱枚举攻击，无论邮箱是否存在，系统都应返回相同的成功提示

#### 邮箱验证功能

- **FR-013**: 用户注册成功后，系统必须自动发送验证邮件到注册邮箱
- **FR-014**: 验证邮件必须包含：验证链接、有效期说明（48小时）、欢迎信息
- **FR-015**: 系统必须生成带有唯一令牌的邮箱验证链接
- **FR-016**: 系统必须验证令牌的有效性（未过期、未使用、匹配用户）
- **FR-017**: 验证成功后，用户账户状态必须更新为"已验证"
- **FR-018**: 验证成功后，系统必须显示成功页面并引导用户登录或前往首页
- **FR-019**: 未验证邮箱的用户登录后，系统必须在页面顶部显示验证提醒横幅
- **FR-020**: 验证提醒横幅必须包含"重新发送验证邮件"按钮
- **FR-021**: 系统必须对验证邮件发送进行频率限制（同一用户5分钟内最多发送3次）

#### 邮箱更改功能

- **FR-022**: 系统必须在账户设置页面提供更改邮箱功能
- **FR-023**: 用户提交新邮箱后，系统必须发送验证邮件到新邮箱地址
- **FR-024**: 新邮箱验证成功前，旧邮箱必须保持有效
- **FR-025**: 新邮箱验证成功后，系统必须更新用户邮箱地址
- **FR-026**: 新邮箱验证成功后，系统必须发送安全通知到旧邮箱
- **FR-027**: 系统必须拒绝将邮箱更改为已被其他账户使用的邮箱

#### 邮件发送功能

- **FR-028**: 系统必须配置SMTP邮件服务用于发送邮件
- **FR-029**: 所有邮件必须使用统一的发件人名称和地址
- **FR-030**: 所有邮件必须包含品牌标识和友好的邮件模板
- **FR-031**: 邮件发送失败时，系统必须记录错误日志但不向用户暴露技术细节
- **FR-032**: 系统必须记录所有邮件发送记录（收件人、类型、时间、状态）

### Key Entities

- **PasswordResetToken**: 密码重置令牌
  - 属性：令牌字符串、用户ID、创建时间、过期时间、使用状态
  - 关系：关联到User实体
  
- **EmailVerificationToken**: 邮箱验证令牌
  - 属性：令牌字符串、用户ID、邮箱地址、创建时间、过期时间、使用状态
  - 关系：关联到User实体
  
- **EmailLog**: 邮件发送日志
  - 属性：收件人邮箱、邮件类型（验证/重置/通知）、发送时间、发送状态、错误信息
  - 关系：可关联到User实体（可选）
  
- **User**: 用户（扩展现有实体）
  - 新增属性：email_verified（布尔值，邮箱是否已验证）、email_verified_at（验证时间）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在3分钟内完成密码重置流程（从请求到登录成功）
- **SC-002**: 用户可以在2分钟内完成邮箱验证流程
- **SC-003**: 密码重置邮件和验证邮件在1分钟内送达用户邮箱（95%的情况下）
- **SC-004**: 系统能够处理每小时1000次密码重置请求而不出现性能下降
- **SC-005**: 90%以上的用户在首次尝试时成功完成密码重置
- **SC-006**: 因密码遗忘导致的支持工单减少80%
- **SC-007**: 邮箱验证率达到70%以上（注册用户中完成验证的比例）
- **SC-008**: 所有敏感操作（密码重置、邮箱更改）都有完整的审计日志可追溯

## Assumptions

- 用户注册时已提供有效的邮箱地址
- 系统已配置可用的SMTP邮件服务
- 用户能够正常接收和访问邮件（邮箱未满、未被拦截）
- 系统使用安全的令牌生成算法（如UUID v4或加密安全的随机字符串）
- 密码重置链接和验证链接使用HTTPS协议确保传输安全
- 系统已实现基本的用户认证功能（登录、注册）
- 邮件模板使用HTML格式，支持响应式设计
- 系统部署在支持异步任务队列的环境中（用于邮件发送）

## Dependencies

- 现有的用户认证系统（Feature 005）
- SMTP邮件服务配置（可使用SendGrid、AWS SES、阿里云邮件推送等服务）
- 异步任务队列（如Celery、Redis Queue）用于后台发送邮件
- 邮件模板系统（可使用Jinja2模板引擎）

## Security Considerations

- 密码重置令牌和验证令牌必须使用加密安全的随机生成器
- 令牌必须足够长（至少32个字符）以防止暴力破解
- 令牌必须有明确的过期时间，过期后自动失效
- 密码重置请求不应泄露用户是否存在（防止邮箱枚举）
- 所有重置和验证链接必须使用HTTPS协议
- 密码重置成功后，应考虑使现有登录会话失效（可选）
- 频率限制机制防止恶意用户滥用邮件发送功能
- 敏感操作应记录详细日志用于安全审计
